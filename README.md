# Что приготовить сегодня

Приложение для телефона, которое каждый день отвечает на вопрос «что сегодня приготовить?». Открыл — увидел несколько подходящих блюд — выбрал — готовишь.

Это PWA: обычный сайт, который ставится на Android через Chrome и выглядит как приложение. Сервера нет, аккаунтов нет, после первой загрузки всё работает без интернета.

**Что умеет**

- **Сегодня** — 4 блюда под время суток, «Показать другие», «Удиви меня». Не повторяет то, что показывал за последние 7 дней.
- **У меня есть** — отмечаете продукты, получаете рецепты по проценту совпадения с подписью «не хватает: …» и подсказками замен.
- **Каталог** — 427 рецептов с поиском и фильтрами (время, калории, белок, диеты, кухня, тип, сложность, оборудование).
- **Рецепт** — пересчёт порций, таймеры в шагах, режим «Готовлю» (один шаг на экране, крупный шрифт, экран не гаснет).
- **Избранное и список покупок** с группировкой по отделам магазина.
- **Профиль** — диеты, аллергии и исключённые продукты действуют везде; тема; цель по калориям.

## 1. Как запустить у себя на компьютере

Нужен [Node.js](https://nodejs.org/) версии 20 или новее (скачайте «LTS» и установите как обычную программу).

Откройте терминал в папке проекта и выполните один раз:

```bash
npm install
```

Дальше приложение запускается одной командой:

```bash
npm start
```

В терминале появится адрес вида `http://localhost:5173` — откройте его в браузере. Пока команда работает, любые изменения в файлах сразу видны на странице. Остановить: `Ctrl + C`.

Другие команды:

| Команда | Что делает |
| --- | --- |
| `npm start` | проверяет базу и запускает приложение для разработки |
| `npm run validate` | только проверяет базу рецептов и продуктов |
| `npm test` | запускает автоматические тесты подбора и фильтров |
| `npm run build` | собирает готовый сайт в папку `dist` |
| `npm run preview` | открывает собранный сайт из `dist` (как он будет выглядеть после публикации, с офлайн-режимом) |
| `npm run photos` | ищет фото для рецептов, у которых их нет |
| `npm run icons` | перерисовывает иконки приложения |

## 2. Как выложить в интернет (бесплатно)

Самый простой путь — GitHub Pages. Автодеплой уже настроен: после первой настройки сайт будет обновляться сам при каждом изменении.

1. Зарегистрируйтесь на [github.com](https://github.com/) и создайте новый **публичный** репозиторий, например `chto-prigotovit` (кнопка «New», больше ничего не отмечайте).
2. Загрузите в него проект. Проще всего через [GitHub Desktop](https://desktop.github.com/):
   - установите GitHub Desktop и войдите в аккаунт;
   - `File → Add local repository…` → выберите папку проекта → согласитесь «create a repository»;
   - внизу слева напишите любое описание (например, «первая версия») и нажмите **Commit to main**;
   - нажмите **Publish repository**, снимите галочку «Keep this code private», подтвердите.
3. На сайте GitHub откройте репозиторий → **Settings → Pages** → в поле **Source** выберите **GitHub Actions**.
4. Откройте вкладку **Actions**. Там идёт сборка «Deploy» (2–3 минуты). Если она не началась, нажмите **Run workflow**. Когда появится зелёная галочка, сайт доступен по адресу:

   `https://ВАШ_ЛОГИН.github.io/chto-prigotovit/`

5. Дальше всё просто: изменили что-то в проекте → в GitHub Desktop **Commit** → **Push** → через пару минут сайт обновился.

**Как поставить на телефон.** Откройте ссылку в Chrome на Android. Появится баннер «Добавить на главный экран» (или меню ⋮ → «Установить приложение»). После установки приложение открывается с главного экрана и работает без интернета.

**Другие хостинги.** Проект не привязан к GitHub: пути внутри относительные, поэтому папку `dist` можно выложить куда угодно.

- **Netlify**: «Add new site → Import from Git», команда сборки `npm run build`, папка публикации `dist`.
- **Cloudflare Pages**: то же самое — build command `npm run build`, output directory `dist`.

## 3. Как добавить рецепт

Рецепты лежат в папке `data/recipes/`, по одному файлу на кухню (`russian.json`, `italian.json` и т. д.). Откройте нужный файл в любом текстовом редакторе и добавьте в список новый блок по образцу:

```json
{
  "id": "moj-sup",
  "cuisine": "russian",
  "type": "soup",
  "name": {"ru": "Мой суп"},
  "description": {"ru": "Короткое описание в одну строку"},
  "activeMinutes": 15,
  "totalMinutes": 40,
  "difficulty": 1,
  "servings": 4,
  "equipment": ["onepan"],
  "emoji": "🍲",
  "photoQuery": "vegetable soup",
  "ingredients": [
    {"product": "potato", "amount": 360, "unit": "g", "measure": {"qty": 3, "unit": "pc"}},
    {"product": "veg_broth", "amount": 1000, "unit": "ml"},
    {"product": "veg_oil", "amount": 14, "unit": "g", "measure": {"qty": 1, "unit": "tbsp"}, "use": "fry"},
    {"product": "dill", "amount": 15, "unit": "g", "optional": true}
  ],
  "steps": [
    {"text": {"ru": "Обжарьте овощи 5 минут."}},
    {"text": {"ru": "Залейте бульоном и варите 20 минут."}, "timerMinutes": 20}
  ]
}
```

Что означают поля:

| Поле | Значение |
| --- | --- |
| `id` | уникальное имя латиницей через дефис |
| `cuisine` | `russian`, `german`, `italian`, `japanese`, `chinese`, `thai`, `korean`, `mexican`, `mideast`, `georgian`, `indian`, `mediterranean`, `international` |
| `type` | `breakfast`, `main`, `soup`, `salad`, `side`, `snack`, `dessert` |
| `activeMinutes` / `totalMinutes` | время у плиты / общее время |
| `difficulty` | 1 — просто, 2 — средне, 3 — сложно |
| `equipment` | `oven` (нужна духовка), `onepan` (одна сковорода или кастрюля), `multicooker` (можно в мультиварке); можно пустой список `[]` |
| `ingredients[].product` | id продукта из `data/products.json` |
| `amount` + `unit` | количество в граммах (`g`) или миллилитрах (`ml`) на весь рецепт |
| `measure` | удобная мера для человека: `pc` шт., `clove` зубчик, `tbsp` ст. л., `tsp` ч. л., `cup` стакан, `bunch` пучок, `pinch` щепотка, `can` банка, `slice` ломтик |
| `optional` | `true`, если ингредиент по желанию (в калории не входит) |
| `use` | `fry` — масло для жарки, `deepfry` — масло для фритюра (в калории идёт только часть) |
| `timerMinutes` | таймер шага в минутах |
| `photoQuery` | запрос на английском, по которому скрипт ищет фото |

**Калории, БЖУ и метки диет вписывать не нужно** — они считаются автоматически.

После правки выполните:

```bash
npm run validate
```

Скрипт проверит базу и по-русски скажет, что не так: несуществующий продукт, пустой шаг, нереалистичные калории (меньше 50 или больше 1500 на порцию), дубликат и т. п. Если всё хорошо — `npm start`, и рецепт уже в приложении.

**Новый продукт** добавляется в `data/products.json` такой же строкой, как соседние: название, синонимы для поиска, категория (отдел магазина), калории и БЖУ на 100 г, при необходимости плотность `density` (г/мл — для перевода ложек и стаканов в граммы) и вес одной штуки `piece`. Флаг `staple` означает «это есть у всех» (соль, вода, масло).

### Фото

Фото лежат в `public/photos/`, а автор, лицензия и источник каждого — в `data/photos.json` (список авторов выводится в приложении в разделе «О приложении»).

```bash
npm run photos
```

Скрипт ищет снимки на Wikimedia Commons только со свободными лицензиями (CC0, CC BY, CC BY-SA, общественное достояние), сжимает в WebP 800×600 до 80 КБ и записывает авторство. Если первый найденный снимок не подошёл:

```bash
npm run photos -- --pick moj-sup=2
```

```bash
npm run photos -- --query moj-sup="potato soup bowl"
```

```bash
npm run photos -- --drop moj-sup
```

`--pick` берёт следующий вариант, `--query` ищет по другому запросу, `--drop` убирает фото — тогда в приложении показывается цветная плашка с эмодзи. Список рецептов без фото всегда лежит в `data/no-photo.txt`.

Своё фото можно добавить вручную: положите файл `public/photos/<id>.webp` (800×600) и допишите запись в `data/photos.json` по образцу соседних.

## 4. Как устроен проект

```
data/                 исходная база — её и нужно править
  products.json         справочник продуктов (304 шт.)
  recipes/*.json        рецепты по кухням (427 шт.)
  photos.json           авторы и лицензии фото
  no-photo.txt          рецепты без фото (создаётся автоматически)
scripts/
  build-data.mjs        проверка базы + расчёт калорий → public/data/
  fetch-photos.mjs      подбор фото
  photo-sheets.mjs      «контактные листы» для проверки фото глазами
  make-icons.mjs        иконки
src/
  engine/               логика без интерфейса: фильтры, поиск по продуктам, подборка «Сегодня» + тесты
  screens/              экраны
  locales/ru.json       все тексты интерфейса
  ui.tsx                общие элементы (карточка, чипы, шторка, навигация)
  store.ts              что приложение помнит о пользователе (localStorage)
  styles.css            оформление, светлая и тёмная темы
public/                 иконки, фото
.github/workflows/      автодеплой на GitHub Pages
```

Стек: TypeScript, React, Vite, vite-plugin-pwa (стандартный service worker Workbox), Vitest.

### Калории

Считаются в `scripts/build-data.mjs` при каждой сборке:

```
ккал на порцию = Σ (граммы × ккал на 100 г) / (100 × число порций)
```

- Справочные значения продуктов — [USDA FoodData Central](https://fdc.nal.usda.gov/) для сырых продуктов (для типично немецких продуктов вроде шпецле и леберкезе — усреднённые значения с упаковок, сверенные с [Open Food Facts](https://world.openfoodfacts.org/)). Вес в рецептах указан в сыром виде.
- Масло для жарки (`"use": "fry"`) учитывается на 50 %, для фритюра (`"deepfry"`) — на 12 %: остальное остаётся на сковороде.
- Необязательные ингредиенты в расчёт не входят.
- Метки «высокий белок» (от 30 г белка на порцию) и «низкие углеводы» (до 20 г) ставятся по результату расчёта; «вегетарианское», «веганское», «без глютена», «без лактозы» и аллергены — по флагам продуктов, включая необязательные ингредиенты.

В приложении цифры подписаны «примерно»; приложение не даёт диетических рекомендаций.

### Новый язык

Тексты интерфейса — в `src/locales/ru.json`, в коде строк нет. Чтобы добавить язык: скопируйте файл (например, в `de.json`), переведите и подключите в `src/i18n.ts` (две строки, там есть комментарий). Названия рецептов, шаги и продукты в базе хранятся как `{"ru": "…"}` — рядом дописывается `"de": "…"`; если перевода нет, показывается русский текст.

### Данные пользователя

Избранное, продукты, список покупок и настройки хранятся только в браузере на устройстве (localStorage) и никуда не отправляются. Политика конфиденциальности — в приложении: «Профиль → Политика конфиденциальности».

### Лицензии фото

Фотографии взяты с Wikimedia Commons и принадлежат их авторам; лицензия каждого снимка указана в `data/photos.json` и в разделе «О приложении». Снимки обрезаны и уменьшены. Фото под CC BY-SA остаются под той же лицензией.
